ProseMirror × mp-darkmode · B(b) 纯视图方案 PoC

目标：验证 ① decoration 的 class + !important 能否覆盖 mark 渲染出的 inline color；② 输入时 decoration 区间能否正确延展继承。

当前：Light Mode（doc 恒为 LM）
验证步骤：
  1. 点「切到 Dark Mode」：看第一段的红字、绿字是否都变成灰白。
    · 变灰白 → !important 覆盖成功，B(b) 成立；
    · 仍是红/绿 → decoration 被渲染在 mark span 外层、盖不住内层 inline color，需走下方 plan B。
  2. 保持 DM 态，在红字中间点一下、打几个字：看新字是否也为灰白、且 decoration 不断裂（验证 inclusiveStart/End 区间延展继承）。
  3. 在红字右边界后紧挨着打字：看新字是否「延续红字组」还是「落回普通组」——确认边界 inclusive 行为是否符合预期。
  4. 切回 Light Mode：确认 doc 本身颜色不变（decoration 是纯视图态，doc 恒 LM）。
  5. 打开 DevTools 看红字那段的 DOM 结构：确认 decoration 的 <span class="pm-dm-fg"> 与 mark 的 <span style="color:#e00"> 的嵌套顺序（谁在内层）。
如果验证步骤 1 失败（红/绿字盖不住）的 plan B：
  • B-1 让 color mark 的 toDOM 感知全局 DM 状态：DM 态时直接输出算法转换后的 DM 色，而非原色。缺点是把 DM 逻辑渗进 schema、且 toDOM 读外部状态不优雅。
  • B-2 用 mark view / node view 接管渲染：在 view 层根据 DM 状态覆盖 mark 的样式输出，比 toDOM 干净，能拿到外部 DM 开关与算法结果。
  • 两者都仍保持「doc 恒 LM」，只是把「覆盖 LM 颜色」的手段从 decoration 换成 markView —— B(b) 的「doc 恒 LM」收益不丢。
